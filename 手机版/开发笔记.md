# 我的播放器 (com.louis.myplayer)
Native Kotlin shell + Media3 1.4.1 (ExoPlayer + MediaSessionService) + WebView UI (assets/web, served by WebViewAssetLoader, JS bridge `Android`).

Rebuild (sandbox is aarch64; uses arm64 aapt2 from lzhiyong/android-sdk-tools via android.aapt2FromMavenOverride):
    ./mkprops.sh          # refresh proxy creds into gradle.properties
    ANDROID_HOME=~/android-sdk ~/gradle-8.9/bin/gradle :app:assembleRelease
    cp app/build/outputs/apk/release/app-release.apk out/myplayer.apk
Signing key: keystore/myplayer-debug.jks (alias myplayer / pass android). KEEP IT: future updates must use the same key to install over the old app.
Toolchain (outside /workspace, not persistent): ~/android-sdk (platform 34, build-tools 34.0.0 with arm64 binaries swapped in), ~/gradle-8.9, apt openjdk-21.

## In-app updater (since 1.1 / versionCode 2)
- Host: `UPDATE_BASE_URL` BuildConfig field, default https://shiyin.example.com (override: `gradle -PupdateBaseUrl=https://… :app:assembleRelease`).
- Server layout: `/version.json` {versionCode, versionName, apk, notes, sha256} + the APK next to it.
- Code: `Updater.kt` (check / download to cacheDir/update / sha256 verify / PackageInstaller session, ACTION_VIEW+FileProvider fallback; `UpdateInstallReceiver`), bridge methods in MainActivity (`checkUpdate`, `startUpdate`, `cancelUpdate`), UI in app.js (设置 →「检查更新」, launch banner, update sheet). Silent launch check ≤ once/12h (Kv `upd_last_check`, cached result `upd_latest`).
- Release a new version: bump versionCode/versionName in app/build.gradle.kts → build → `publish/prepare.sh "更新说明"` → upload the contents of `publish/site/` to Cloudflare Pages. The script refuses to run if the APK isn't signed with the 1.0 key (cert SHA-256 48bca8fe…0901586).

## 1.2 (versionCode 3) — fixes
- Root cause of both "no music found" and "检查更新没反馈" in 1.1: app.js used `App.onUpdateCheck = …` (line ~429) before `window.App = window.App || {}` (line ~657); in strict mode that threw ReferenceError at load, so the rest of the script (startup scan, permission button, App.onPermission/onScanDone/onUpdateCheck) never ran. `window.App` is now defined at the top. 1.1 therefore cannot self-update → 1.2 must be sideloaded once.
- Library.scan: MediaScannerConnection.scanFile on common folders (+ unindexed files found by walking them), MediaStore Audio query with no IS_MUSIC/≥30 s filter (system sounds/ringtone dirs excluded, <5 s skipped), Files query by extension for odd MIME, MMR fills unknown durations, direct java.io.File tracks for files MediaStore lacks (works with 所有文件访问). WMA/APE/DSD/AIFF/WV/TTA are skipped and counted (Media3 1.4.1 has no extractor). Scan report (searched dirs, counts, skipped) in library.json → empty state.
- Scans run on a dedicated executor; auto rescan on resume when the MediaStore audio fingerprint (version/count/max generation_modified/all-files state) changed.
- Updater: dedicated cached thread pool, 6 s connect / 8 s read, hard 12 s ceiling, every Throwable → JSON {ok:false,error,message}; UI shows the result inline in the settings row + toast (toast now position:fixed, z-index 9999, outside #app); JS 15 s watchdog.

## 1.3 (versionCode 4) — 歌词自动转为简体中文
- `assets/web/t2s.js` (~82 KB, +38 KB in APK): OpenCC (Apache-2.0) Traditional→Simplified in plain JS, longest-match phrases then characters, chain = tw2s/hk2s merged: CJK compat → TWVariantsRevPhrases+HKVariantsRevPhrases / reverse TWVariants+HKVariants (著→着 except 著名/顯著…, 裡→裏) → TSPhrases + TSCharacters. Generated by /workspace/work/opencc/gen_t2s.py from the master dictionaries in that folder; matches python OpenCC 1.4.2 tw2s on a 2,773-line lyrics/wiki corpus (1 line differs: 防衞→防卫, which is better).
- app.js: setting 「歌词转简体」 (Kv `t2sLyrics`, default ON). Conversion happens at display time in `App.onLyrics` (so .lrc, embedded, LRCLIB, cached and manual lyrics all convert, nothing on disk changes), in LRCLIB search results, and for track title/artist/album in `loadLibrary` (originals kept as `oTitle/oArtist/oAlbum`; lyric-offset keys and the manual-search prefill use the originals). In-app search also matches a traditional keyword.
- Not converted: the native notification / lock-screen media title (Kotlin side), playlist names.
- Tests: /workspace/work/jstest/t2s.test.js (unit), dom_t2s.js (jsdom integration), plus harness.js / dom.js (1.2 regressions).

## 2.2 (versionCode 13) — 传到电脑修复
- Real-world failure: the PC could not reach the phone at all (UDP discovery, manual IP and even the PC browser on :18520 failed). Likely HyperOS freezing the app/process when it leaves the foreground, and/or inbound connections to the phone being blocked (phone VPN, router AP isolation).
- `SyncService.kt`: foreground service (`dataSync`, Android 14 `FOREGROUND_SERVICE_DATA_SYNC`), notification 「拾音 正在等待电脑连接」 + 停止, WifiLock (FULL_HIGH_PERF) + partial wake lock, auto-stop after 30 min without a real request (`SyncServer.lastActivity`). Bridge `syncStart/syncStop/syncStatus` start/stop it; closing the sheet (完成) stops it, backgrounding does not.
- `SyncServer.candidates()`: every IPv4 (wifi/hotspot/eth/vpn/mobile) shown on the sheet; VPN detected via ConnectivityManager → hint.
- `ReverseClient.kt` 「手机连电脑」: UDP 18523 `SHIYIN_FIND_PC` discovery, handshake `SHIYIN-REVERSE/1 <code> {json}` to PC TCP 18522, pool of 4 outbound connections, each serves one HTTP request through `SyncServer.serveReverse` (same handler, no code check), reconnect with back-off. Raw sockets, so `usesCleartextTraffic=false` is irrelevant. Bridge `pcDiscover/pcConnect/pcDisconnect` → `App.onPcFound/onPcConnect`.
- `Exporter.kt`: 拾音数据.json + .拾音封面/ in Music/拾音 (hooks: Meta.save, Covers.setCustom/clearCustom, Kv.set playlists/exportData, scan done, first resume). Setting 「导出歌单和改名到拾音文件夹」 (Kv exportData, default on).
- Protocol: /workspace/work/shiyin-sync-protocol.md (v1.1 section).
- Tests: `gradle :app:testReleaseUnitTest` (ReverseClientTest with a fake PC socket, ExporterTest; JVM via org.json + unitTests.isReturnDefaultValues). Interop with the real Go hub: `SHIYIN_INTEROP=/tmp/hub go test -run Interop .` in shiyin-pc + `SHIYIN_INTEROP=/tmp/hub gradle :app:testReleaseUnitTest` at the same time. UI: `node /workspace/work/jstest/dom_sync22.js` (jsdom in /tmp/jsd: `cd /tmp/jsd && echo '{}' > package.json && npm i jsdom@24 --cache /tmp/npmcache`).
- Toolchain is rebuilt by /workspace/tools/setup-android.sh (persistent parts in /workspace/tools). The SDK manager prints 407 proxy warnings while fetching manifests; the build still succeeds.
